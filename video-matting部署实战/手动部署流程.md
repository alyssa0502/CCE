# video-matting CCE Turbo 手动部署流程（人工操作 Runbook）

> 不依赖 skill 脚本，全程可用华为云控制台 + SSH + kubectl 完成。API/curl 作为控制台做不到或更快时的备选。
> 所有参数取 2026-11-03/04/05 三轮实测固化值（cn-east-3 上海一，GPU = NVIDIA L2 24G）。
> 预计总耗时 30~60 分钟；GPU 节点按需计费是费用大头，**用完请按 §12 拆除**。

## 1. 网络准备（VPC / 子网 / 安全组）

**控制台路径**：网络控制台 → 虚拟私有云 VPC → 创建虚拟私有云。

| 资源 | 固化值 |
|---|---|
| VPC CIDR | `192.168.0.0/16` |
| 子网 CIDR | `192.168.0.0/24`，网关 `192.168.0.1`，开启 DHCP |
| 安全组 | 放通入方向 TCP 22（SSH）与 TCP 8001（服务） |

### 1.1 ⚠ 必做：修正子网 DNS（最大坑，跳过 = 节点永远卡 Installing）

CCE 默认给子网填的 DNS `100.125.36.53 / 100.125.5.151` 在部分 VPC 主位**不可达**，导致节点 cce-agent 下载失败、永远卡 `Installing`。子网创建完成后**立即**改为：

```
首选 DNS：100.125.1.250
备选 DNS：100.125.36.53
```

- **控制台路径**：VPC 控制台 → 子网 → 修改 → 改 DNS 服务器（有的界面版本此处改的是 v1 子网，需确认生效到 ENI 子网）。
- **API 口径（已实测可靠）**：v1 子网接口无 PUT，必须走 neutron v2.0。注意 CCE 要用两个不同的 ID：v1 子网响应的 `id` 是 network ID（给集群 hostNetwork.subnet），`neutron_subnet_id` 才是 IPv4 子网 ID（给 Turbo eniNetwork 和本步 DNS 修改用）：

```bash
PUT https://vpc.{region}.myhuaweicloud.com/v2.0/subnets/{neutron_subnet_id}
{"subnet": {"dns_nameservers": ["100.125.1.250", "100.125.36.53"]}}
```

ENI 子网（Turbo 容器网段，若单独建）同样执行一次。

- **已卡死节点的抢救**：SSH 登录节点，把 `/etc/resolv.conf` 首选改为 `100.125.1.250`，`nmcli con mod "System eth0" ipv4.dns "100.125.1.250 100.125.36.53" ipv4.ignore-auto-dns yes && nmcli con up "System eth0"`，然后重跑 `bash /var/lib/cloud/instance/scripts/runcmd`，约 1 分钟节点转 Active。

### 1.2 安全组附加规则（部署后期要用，先记下）

- TCP 8001 入方向：源 = VPC 网段 `192.168.0.0/24`（垫片用，**不要放 0.0.0.0/0**——垫片是无鉴权上传口）。
- TCP 10250 入方向：源 = VPC 网段（apiserver→kubelet；缺了 `kubectl logs/exec` 全超时）。

**控制台路径**：CCE 控制台 → 购买集群。

| 项 | 固化值 |
|---|---|
| 类型/版本 | **CCE Turbo**，v1.36 |

轮询到 `status.phase = Available`（5~15 分钟）。

## 4. 安装 GPU 驱动（gpu-beta 插件 = 路线A）

> 用户指定口径：驱动必须走 CCE 插件（界面安装等效），不用驱动预装镜像。

**控制台路径**：CCE 控制台 → 集群详情 → 插件管理 → 搜索 `gpu-beta`（CCE AI 套件 NVIDIA GPU）→ 安装，默认参数。

### 4.1 关键语义（控制台装不上/起 CrashLoop 时必看）

1. **池节点**（经节点池创建）：operator 自动填华为桶驱动 URL，默认参数即可。
2. **自由节点**（单买直加，无 nodepool；节点 label `cce.cloud.com/cce-nodepool-id=""`）：operator 生成的 NvidiaNodeConfiguration 为空 → installer 无 URL 直接 CrashLoop。**必须显式补驱动 URL**，走插件更新 API：

```bash
PUT /api/v3/addons/{cluster_id}/{addon_id}
# values.custom 增加：
{
  "values": {
    "custom": {
      "nvidia_driver_download_url": "<驱动.run 完整URL>",
      "is_driver_from_nvidia": true
    }
  }
}
```

3. **`is_driver_from_nvidia` 语义（踩过 SignatureDoesNotMatch 才懂）**：
   - `false` = URL 被当**相对路径**拼到 `obs.{region}.myhuaweicloud.com/cce.{region}/cce-addon/GPU-driver/` 基路径后 → 自建桶地址必炸；
   - `true` = **原样透传**进 DS env `NVIDIA_DRIVER_DOWNLOAD_URL`。凡自定义桶地址一律 `true`。
4. **驱动 URL 来源**（两选，均不需要公网/NAT，OBS 走内网）：
   - 华为 OBS 真源（匿名可拉）：`https://hgcs-drivers-cn-east-3.obs.cn-east-3.myhuaweicloud.com/release/driver/tesla/NVIDIA-Linux-x86_64-{版本}.run`
   - 自有桶 `obs-mcn` 中转：本地（或任意可出网机器）下载 NVIDIA 官网 `.run`（注意 Akamai CDN 403 华为云 IP，节点直下必 403），V2 签名 PUT 上传 `obs-mcn`，生成 48h 预签名 GET URL 填入。
5. **改插件 values = 卸载重装**：同版本 PUT 报 400 `unsupported upgrade type` → `DELETE /api/v3/addons/{cluster_id}/{addon_id}` 等卸净（GET 404）再 POST 安装（annotations `addon.install/type: install`）。**重装后 coredns / everest-csi-controller / nvidia-operator 副本会被 helm 拉回 2，单节点集群必须手动压回 1**：
   ```bash
   kubectl -n kube-system scale deploy coredns --replicas=1
   kubectl -n kube-system scale deploy everest-csi-controller --replicas=1
   kubectl -n kube-system scale deploy nvidia-operator --replicas=1   # 以实际部署名为准
   ```

### 4.2 验证口径（装完必验，三项）

```bash
# ① 调度层：节点容量出现 GPU
kubectl get node <节点名> -o jsonpath='{.status.capacity.nvidia\.com/gpu}'   # 应为 1

# ② 节点侧
ssh root@<节点> "cd /usr/local/nvidia/bin && ./nvidia-smi"

# ③ 容器侧（device-plugin 镜像起临时 Pod）
kubectl run gpu-check --rm -it --image=nvidia:device-plugin? \
  --overrides='...' -- nvidia-smi     # 容器内 cd /usr/bin && ./nvidia-smi
```

简易容器验证：`kubectl apply` 一个用同集群任意 GPU 镜像、`limits: nvidia.com/gpu: 1` 的 Pod，`kubectl exec <pod> -- nvidia-smi`，应显示 L2 24G（23034 MiB）。

## 6. 部署工作负载

### 6.1 镜像

直接用 SWR 正典镜像（跳过构建）：

```
swr.cn-east-3.myhuaweicloud.com/mcn-poc/video-matting:20261104
```

CCE 同账号免密拉取。自建镜像路径见附录 B。

### 6.2 写 Deployment + Service

取基准 YAML：本目录 `assets/vm_workload.yaml`，**只有两处占位符**要填：

| 占位符 | 填什么 |
|---|---|
| `<SWR_IMAGE>` | `swr.cn-east-3.myhuaweicloud.com/mcn-poc/video-matting:20261104` |
| `<OSS_API_DOMAIN_VALUE>` | `http://<节点私网IP>:8001`（§7 垫片地址。**绝对不许留代码默认值**——默认值指向客户生产 OSS） |

YAML 已内置全部实测配置：单卡 limits、滚动 `maxSurge:0/maxUnavailable:1`（单卡节点必须先删旧再拉新）、`/dev/shm` 32Gi、健康/存活探针、`nodeSelector: accelerator=nvidia-l2`（§3 已打标签）、env `GPU_CONCURRENCY_LIMIT=1` / `SAM2_COMPILE=false` / `OSS_API_DOMAIN` 钉死。

Service 关键点（YAML 已内置）：`type: LoadBalancer` + 注解：

```yaml
kubernetes.io/elb.class: "union"                    # 共享型 ELB
kubernetes.io/elb.autocreate: '{"type":"public","bandwidth_name":"video-matting-bw","bandwidth_size":100,"bandwidth_sharetype":"PER","bandwidth_chargemode":"traffic","eip_type":"5_bgp"}'
```

> ⚠ 两个坑：
> - `eip_type: 5_bgp` 缺了 CCE admission 直接拒整个 Service；
> - 注解值必须是**单行合法 JSON**——YAML 注释绝不能写进 `>` 折叠块标量（会被当内容解析，报 `invalid character '#'`）。

部署：

```bash
kubectl label node <节点名> accelerator=nvidia-l2     # 若 §3 没打
kubectl apply -f vm_workload.yaml
kubectl get pods -l app=video-matting -w              # Pending/ContainerCreating → Running
kubectl get svc video-matting-svc                      # 取 EXTERNAL-IP = ELB 公网 IP
```

### 6.3 拉取 401 修复（出现过一次）

若 Pod `ImagePullBackOff`、报 anonymous 401：default ServiceAccount 没挂 imagePullSecrets。

```bash
kubectl patch sa default -n default --type=merge -p '{"imagePullSecrets":[{"name":"default-secret"}]}'
kubectl delete pod -l app=video-matting    # 必须删 Pod 重建，存量 Pod 不补
```

## 7. 数据隔离垫片（铁律，服务起来前后均可，但必须做）

镜像内代码的 `OSS_API_DOMAIN` **默认值指向客户生产 OSS**。垫片伪造存储 API，让上传结果落在节点本地目录，客户 OSS 物理不可达。

```bash
# 本机 → 节点
scp -i video-matting-key.pem assets/obs_shim.py root@<节点公网IP>:/root/

# 节点上（OBS_SHIM_ADVERTISE_IP 必填，填节点私网 IP，漏了预签名 URL 是废的）
ssh root@<节点公网IP>
OBS_SHIM_ADVERTISE_IP=<节点私网IP> nohup python3 /root/obs_shim.py >/root/shim.log 2>&1 &
curl http://127.0.0.1:8001/ping        # → pong
```

确认三件事闭环：
1. 垫片进程在跑（`/root/shim.log` 有 listening 行）；
2. Deployment env `OSS_API_DOMAIN=http://<节点私网IP>:8001` 已钉死（`kubectl exec <pod> -- env | grep OSS_API_DOMAIN`）；
3. SG 规则 8001 只放 VPC 网段（§1.2）——垫片无鉴权，绝不露公网。

垫片接口（与真实 openapi 形状一致，服务无感）：`generateTempUploadKeyV2` → 本地 URL；`PUT /upload/<name>` → 落盘 `/root/vm-build/obs_relay/`；`presignV2` → 本地下载 URL。之后把 `obs_relay/` 里的结果用自有 AK V2 签名 PUT 转传 `obs-mcn`。

## 8. 健康检查 / 预热 / E2E 验证

对 ELB 公网 IP（`kubectl get svc` 拿到的 EXTERNAL-IP）：

```bash
# ① 健康检查（模型加载 30~60s，期间 503，轮询到 200 {"status":"ok"}）
curl http://<ELB_IP>:8001/health

# ② 预热（离线加载 Florence-2 + SAM2，超时给 90s）
curl -X POST http://<ELB_IP>:8001/initialize
# → {"status":"warmed","cached":false,"duration_ms":...,"florence_ms":...,"sam2_ms":...,"compile":false}

# ③ URL 推理（NDJSON 流式：received → meta → data* → finish）
# 测试视频：OBS 控制台 obs-mcn → video-matting-test/test_person.mp4 → 生成预签名下载 URL（V2，48h）
curl -N -X POST http://<ELB_IP>:8001/video/segment_url \
  -H 'Content-Type: application/json' \
  -d '{"video_url":"<预签名URL>","mode":"auto"}'

# ④ 上传推理（multipart）
curl -N -X POST http://<ELB_IP>:8001/video/segment_stream -F file=@test.mp4 -F mode=auto
```

验收标准：`/initialize` 返回 `warmed`；推理流完整出现 `status`→`meta`→`data`→`finish`。

> ⚠ **验证只打一次**：单 Pod 连续第二个请求必 CUDA OOM（见 §11）。验完这条就别再打了。

## 9. ELB 白名单收尾（必做）

服务目前裸奔公网，必须挂白名单。

**控制台路径**：ELB 控制台 → 访问控制 → IP 地址组 → 创建（放行用户出口 IP，固化值 `111.119.234.6`）→ 弹性负载均衡列表 → 找到 CCE 自动创建的共享型 ELB（按 EIP 找）→ 监听器（8001）→ 修改 → 访问控制 → 白名单 → 绑定地址组。

**API 口径**（已实测，含键名坑）：

```bash
# 键名坑：publicips[].publicip_address（无下划线）或 vip_address 匹配 ELB
GET /v3/{pid}/elb/loadbalancers?limit=100
# 监听器挂白名单：键是 ipgroup.ipgroup_id（不是 id）
PUT /v3/{pid}/elb/listeners/{listener_id}
{"listener": {"ipgroup": {"ipgroup_id": "<地址组ID>", "enable_ipgroup": true, "type": "white"}}}
```

实测效果：外部非白名单 IP **TCP 握手都过不了**；VPC 内机器仍能访问属正常（hairpin 内网直达 Pod ENI，不经监听器）——**验证白名单要用 VPC 外的独立 IP**（预期 TCP 超时）。

## 11. 已知限制（交付必说明）

1. **单 Pod 一请求**：连续第二个请求必 OOM（代码 finally 缺 `del`+`torch.cuda.empty_cache()`，请求后仍占 17.58G），重启 Pod 恢复。已反馈客户修码，修复前按"一 Pod 一请求"运营。
2. **长视频**：开 env `SAM2_OFFLOAD_VIDEO_TO_CPU=true`（24G 单卡跑不了 >22G 显存的视频；代价是变慢）。
3. **双卡不可行**：代码单卡逻辑（第二张卡可见但闲置）；且 cn-east-3 无 2 卡 L2 规格（k8s 整卡调度不跨节点拼卡，gpu:2 必 Pending）。
4. **白名单对 VPC 内无效**：hairpin 不经监听器，正常现象。

## 12. 运维陷阱速查

| 坑 | 处理 |
|---|---|
| 节点永远 Installing | 子网 DNS（§1.1）；已卡节点 SSH 抢救法同节 |
| Installing 态节点删不掉 | DELETE 403（CCE.01403001），Abnormal 态才可删；429 "Resource locked" 轮询到 404 |
| kubectl logs/exec 超时 | SG 放 apiserver→kubelet tcp/10250（VPC 网段） |
| SSH 报 host key 变更 | EIP 复用会换 host key：`ssh-keygen -R <IP>` 后 accept-new |
| Pod OOM（第二个请求） | §11.1，重启 Pod |
| gpu-beta 改配置 400 | 卸载重装 + 副本压回 1（§4.1.5） |
| SWR 凭据 401 | 临时凭据 24h 过期，重新生成 |
| ELB 内网访问不进白名单 | 正常，hairpin；外部 IP 验证 |

## 13. 拆除/回滚顺序（防嵌套删除卡死）

```
① kubectl delete -f vm_workload.yaml          # 先删 Service(解绑 ELB/EIP)再删 Deployment
② 控制台卸载 gpu-beta 插件
③ CCE 删除节点（等 Active/Abnormal 态才删得掉；Installing 态 403）
④ CCE 删除集群
⑤ ELB：确认共享型实例随 Service 删除；IP 地址组手动删
⑥ EIP：解绑后释放；OBS：obs-mcn 保留（数据不删）
⑦ 子网（先 ENI 相关残留）→ VPC
```

## 附录 B：自建镜像路径概要（不用正典镜像时）

> CCE 节点**没有 docker**（containerd + buildkit，硬装 docker 会冲突）。2026-11-04 实测全链路：

1. 节点上传源码包，buildkitd 加 `--addr tcp://127.0.0.1:12345`（15G tar 走 unix socket 必断流，3 次复现）；
2. `buildctl --addr tcp://... build --frontend dockerfile.v0 ... --output type=docker,name=video-matting:{tag},dest=...tar`；就绪判断用 `buildctl debug info`（残留死 socket 会骗过 `[ -S ]`）；
3. `ctr -n k8s.io images import` → 导入后真名是 `docker.io/library/video-matting:{tag}`（ctr 不做短名归一化，tag/push 必须 FQDN）；
4. SWR 临时登录指令：`POST https://swr-api.{region}.myhuaweicloud.com/v2/manage/utils/secret?projectname={region}`（manage 域名是 **swr-api**，响应头 `X-Swr-Dockerlogin`；凭据 24h 过期）；
5. `ctr images tag` 到 `swr.cn-east-3.myhuaweicloud.com/mcn-poc/video-matting:{tag}` → `ctr images push --user "<u>:<p>"`（层去重，增量推送分钟级）。

正典 tag `20261104` 为隔离保险丝版：默认 `OSS_API_DOMAIN=127.0.0.1:1`、`OSS_BUCKET=obs-mcn`、insta360 引用清零（容器内 grep 已验证）。
